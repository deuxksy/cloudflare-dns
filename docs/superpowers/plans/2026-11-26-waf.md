# Cloudflare Free 호환 WAF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `zzizily.com`과 `zetlabs.net` 두 도메인에 Free 플랜 호환 기본 WAF(Custom Rules 2개 + Rate Limiting 1개)를 OpenTofu로 선언하고 CI 배포를 준비한다.

**Architecture:** 각 도메인 디렉토리(`domain/zzizily/`, `domain/zetlabs/`)가 독립된 R2 state와 CI job을 가지므로, 각 폴더에 `waf.tf`를 추가해 `cloudflare_ruleset` 리소스 2개(`http_request_firewall_custom`, `http_ratelimit`)를 선언한다.

**Tech Stack:** OpenTofu (`>= 1.8.0`), Cloudflare Provider (`~> 5.0`), Cloudflare Rulesets API

**Spec:** [2026-11-26-waf-design.md](file:///Users/crong/git/cloudflare-dns/docs/superpowers/specs/2026-11-26-waf-design.md)

## Global Constraints

- 검증 명령: `cd domain/<도메인> && tofu fmt -check && tofu validate -no-color`
- 로컬 `tofu apply` 금지 — 변경은 PR → CI `tofu plan` 검증 → `main` merge 자동 apply
- Free 플랜 한도 준수: Custom Rules 최대 5개(본 계획은 2개), Rate Limiting 최대 1개(`period = 10`, `mitigation_timeout = 0` with `managed_challenge`, `characteristics = ["cf.colo.id", "ip.src"]`)
- 정상 검색 봇(`cf.client.bot`) 및 `/.well-known/` 경로 오탐 차단 금지
- `zzizily.com`의 기존 `http_request_firewall_managed` phase는 건드리지 않음

## Review Focus

- **SSL/ACME 검증 경로 오탐**: `/.well-known/` 하위 요청이 스캐너 경로 차단 규칙에 걸리지 않도록 expression에 예외 조건이 명시되어야 함
- **정상 검색엔진 봇 차단**: Googlebot 등 `cf.client.bot`이 빈 UA/스캐너 규칙에 의해 차단·챌린지되지 않도록 `not cf.client.bot` 조건 포함
- **Free 플랜 Rate Limit 파라미터 위반**: `period = 10`, `mitigation_timeout = 0` (`managed_challenge`), `characteristics = ["cf.colo.id", "ip.src"]` 외의 값을 쓰면 `zetlabs.net`(Free) 및 `zzizily.com`(Pro) apply가 실패하므로 정확히 일치해야 함
- **정적 에셋 요청으로 인한 Rate Limit 오탐**: HTML 1페이지 로드 시 다수의 `.css`, `.js`, 이미지 요청이 동시 발생하므로 정적 확장자 제외 조건 포함
- **Provider v5 스키마 호환성**: `domain/zzizily`와 `domain/zetlabs` 모두 `tofu validate -no-color`가 오류 없이 통과해야 함

### Task 1: `domain/zzizily/waf.tf` 작성 및 검증

**Files:**
- Create: `domain/zzizily/waf.tf`

**Interfaces:**
- Consumes: `var.cloudflare_zone_id` (`domain/zzizily/main.tf`)
- Produces: `cloudflare_ruleset.waf_custom`, `cloudflare_ruleset.waf_ratelimit`

- [ ] **Step 1: `domain/zzizily/waf.tf` 작성**

`cloudflare_ruleset` 2개를 선언한다:
1. `waf_custom` (`zone_id = var.cloudflare_zone_id`, `name = "default"`, `kind = "zone"`, `phase = "http_request_firewall_custom"`):
   - Rule 1 (`action = "block"`, `enabled = true`): `not cf.client.bot` 이면서 `not starts_with(http.request.uri.path, "/.well-known/")` 이고 스캐너/민감 경로(`/.env`, `/.git`, `/wp-login.php`, `/wp-admin`, `/xmlrpc.php`, `/phpmyadmin`, `/.aws`, `/.ssh`)에 매칭되는 요청 차단
   - Rule 2 (`action = "managed_challenge"`, `enabled = true`): `not cf.client.bot` 이면서 `(http.user_agent eq "" or http.request.version eq "HTTP/1.0")`인 요청 챌린지
2. `waf_ratelimit` (`zone_id = var.cloudflare_zone_id`, `name = "default"`, `kind = "zone"`, `phase = "http_ratelimit"`):
   - Rule 1 (`action = "managed_challenge"`, `enabled = true`): `not (http.request.uri.path.extension in {"css" "js" "png" "jpg" "jpeg" "gif" "svg" "ico" "webp" "woff" "woff2"})` 조건에 대해 `ratelimit` 블록(`characteristics = ["cf.colo.id", "ip.src"]`, `period = 10`, `requests_per_period = 100`, `mitigation_timeout = 10`) 적용

- [ ] **Step 2: 포맷 및 유효성 검증**

Run: `cd domain/zzizily && tofu fmt -check && tofu validate -no-color`
Expected: Exit code 0, `Success! The configuration is valid.`

- [ ] **Step 3: 커밋**

```bash
git add domain/zzizily/waf.tf
git commit -m "feat(zzizily): add Free-compatible WAF custom and rate-limit rulesets"
```
